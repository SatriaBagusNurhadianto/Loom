# Phase 5 testing

Use `npm run check`, `npm run test:e2e`, and `npm run package`. Use `LOOM_RESEARCH_LIVE=1 npx playwright test tests/e2e/research.spec.ts` for opt-in real arXiv retrieval and installed TeX compilation. The public arXiv check needs networking; no credentials are required. All manuscript fixtures and Zotero test records are synthetic. No personal Zotero library is modified.

## Author workflow

1. Open an ordinary project with a main document declaring `\bibliography{refs}` (BibTeX) or `\addbibresource{refs.bib}` (biblatex). Put the source cursor after a claim. **References** is the magnifying glass immediately before Tools; Tools → Research also opens it. The live source remains mounted behind the shared modal.
2. **Project** searches citation key, title, author, year and DOI. Inspect missing-key notices and duplicate/incomplete/unused states. Unknown fields, comments, string definitions and existing file bytes remain untouched by search/import. Unused entries are informational. Search is explicit-submit; clear returns focus to the field. Up to 100 matching rows render; refine the query to find others. Service output is bounded to 5,000 valid matching records, with omitted/oversized results disclosed.
3. **arXiv** sends only the explicitly submitted query. Search keywords, an arXiv identifier such as `1706.03762`, or its abstract URL. Search results carry provenance and record/abstract-only evidence; the source link opens through the HTTPS-only native boundary. A selected passage can populate the query before sending. Search relevance does not establish scientific support. Cancel/clear/provider switching/close invalidate pending work, including queries waiting behind a save. Rate limits, invalid/partial responses and missing connectivity are explicit; arXiv searches are spaced by three seconds.
4. **Zotero** reads the running desktop application's supported local API. Enable Zotero Settings → Advanced → Allow other applications on this computer to communicate with Zotero. Search and inspect an explicitly selected exported BibTeX entry; importing appends it to the paper, with unknown fields retained. Loom performs GET requests only, stores no library credentials and never edits Zotero. A missing/disabled API explains how to retry. The initial connection is the local personal library (user 0); group/cloud libraries are outside this implementation.
5. Select a record, inspect its metadata/evidence and expand **BibTeX preview**. Select the bibliography and citation command your project supports. Existing identifiers reuse the existing key; title-only matches need an explicit same-source confirmation. A different record with the same key requires a unique key. A matching record's repeated import does not append a duplicate. Missing declared bibliography files appear as new-file options, including when editing an included chapter. Disconnected source files and dynamic macro-based resource/include declarations are not guessed into the main paper.
6. **Import and cite** / **Insert citation** appends an entry only when needed and inserts at the captured cursor. It checks source and bibliography versions before writing. Changed source asks the author to place the cursor again. Writes and recovery reconcile through the existing project bridge; newer writing is not replaced by an old snapshot. Compile using **Create PDF / Update PDF** and verify the bibliography renders.
7. **Discuss with agent** appends the source, identifier, citation key, provenance and evidence to the existing assistant draft, retaining a selected claim. Review/send through the current harness/model. The actual request and conversation retain that evidence; imported BibTeX retains a direct source URL. A draft handoff is not a claim of live model verification or proof that the source supports the claim.
8. At 1440×900 and 720×540, select records, scroll long abstracts/previews, open native selectors, reach actions and close with Escape. Check keyboard search/clear/result activation/focus return and reduced motion. Compare shared fields/buttons with PDF settings.

## Recovery and boundaries

`tests/research.test.ts` exercises real temporary filesystem/SQLite/project models with injected provider responses and interrupted writes. Tests include raw BibTeX preservation, Unicode/identifier identity, selected-root resource membership, oversized partial results, queued cancellation, repeated imports, stale source/key collisions, interruption before the second write, restart/replay, undo and overlapping newer work.

A citation group journals both before/after versions before writing. If interrupted, reopen References → Project. **Finish insertion** and **Undo insertion** replay idempotently after validating the whole group. Newer divergent files block replay. Expand saved versions to inspect/copy the full before/planned/current content. After review, **Keep current files** releases the group without writing either manuscript file; a citation may need manual repair. The original journal is archived in private application data. This is recoverable grouping, not a filesystem-level multi-file atomic transaction. Recovery is independent of Git.

`tests/e2e/research.spec.ts` uses actual sandboxed Electron/preload/utility/SQLite/Yjs/editor/disk paths. Native project selection is stubbed. The Zotero case binds a synthetic read-only local API fixture only when port 23119 is free, exercises the real HTTP/IPC/import path and verifies GET-only traffic. It is not a live Zotero desktop claim. The opt-in arXiv case retrieves the actual identifier, inspects evidence, appends/cites, compiles using real TeX, repeats insertion and verifies no bibliography duplication. Other cases verify narrow/keyboard/draft/search/stale-source/reload behavior.

The broader Phase 2/3/4 suites remain regression gates. Live external agents, installed/cross-platform packaging and physical disk/power-loss testing are not implied by these checks. Current results and reviewer responses are recorded in [project status](../project_status.md) and [Phase 5 review](phase-5-review.md).

For the authorized optional native-agent check, run `LOOM_RESEARCH_AGENT_LIVE=1 npx vitest run tests/research-live.test.ts`. It uses the available OpenCode Big Pickle model with a synthetic paper and actual arXiv abstract, checks retained source provenance in the public user request, performs the requested native edit, compiles with real TeX and safely reverts only the agent revision. Default tests never make model calls. Use `LOOM_E2E_EXECUTABLE="$PWD/release/linux-unpacked/loom" npx playwright test tests/e2e/research.spec.ts` after packaging to verify the same synthetic desktop flows against the distributable executable.
